  'Stop-loss:' detail line with the live trigger + %-from-now. The buy-side
  cancel+book logic was extracted from execute_buy into
  cancel_pending_buy_and_book() and is shared by both paths (log wording there

Sep 1 - FIX: wallet-vs-grid drift (tracked position diverging from real Kraken
  balance) + one-time reconciliation. Root cause: 17 coins share one API key;
  concurrent private REST calls raced into Kraken "EAPI:Invalid nonce" errors
  (75 in the logs, 43 in one 08-22 reconnect storm). On a nonce-failed CANCEL,
  check_pending_sell/buy dropped pending_*_order anyway, orphaning a still-live
  order that later filled unbooked -> tracked drifted from the wallet (e.g. TAO
  tracked 0.46451 vs real 0.01844, then 590 "volume minimum not met" retries).
  Fixes (helpers/coin_runner.py, conductor.py):
   1. install_private_call_serialization(): all private REST calls go through
      one asyncio.Lock + a strictly-monotonic nonce, so they can't race.
      Installed on the shared exchange at startup. Public/WebSocket untouched.
   2. Cancel paths (check_pending_sell/buy, cancel_pending_{buy,sell}_and_book)
      no longer drop tracking when a cancel raises -- the order is still live,
      so we keep it and retry; callers (execute_buy force, execute_target_sell)
      abort rather than stack an order on top of a live one.
   3. live_sellable_qty() floors at the market minimum: returns 0 (skip) instead
      of spamming below-minimum orders -- kills the dust retry loop.
   4. check_pending_buy closed-with-no-filled now warns instead of silently
      assuming a full fill.
   5. reconcile_all_to_exchange(): at startup (live only) each coin's tracked
      position is mirrored to the real Kraken balance BOTH ways -- shortfalls
      scale down / clear as dust, surpluses scale up -- preserving avg_entry and
      grid level count. Keeps tracked == wallet across restarts. (Operator chose
      "match the exchange both ways"; surplus coins are now managed & sold by the
      grid.) Coins with no open position are left flat.
  One-time cleanup applied to data/state_*.json (backup: backup_reconcile_*/):
   INJ 7.3587 -> 0 (ghost cleared), TAO 0.46451 -> 0 (dust cleared),
   AAVE/ADA/HYPE/MON/PUMP/VVV/XMR/ZEC scaled UP to the real balances
   (e.g. ADA 3739 -> 7040, PUMP 64988 -> 143884), avg entry preserved.
  Paper wallet.json is unused in live mode (frozen at $650) -- unchanged.
  NOTE: restart the bot to apply. Startup reconciliation will re-mirror to
  whatever Kraken shows at launch (idempotent now that state == balance).

Sep 9 - adding or enabling a coin no longer needs a restart.
  conductor.run() used to await one asyncio.gather() over a fixed list of coin
  tasks, so a task created later was outside the supervision: its exceptions
  went unlogged and shutdown didn't cancel it. Coin tasks now live in a set with
  a done-callback that logs failures and notices when the last one ends, and the
  run loop waits on an Event instead. Shutdown behaviour is unchanged --
  verified by cancelling the main task on both the old and new code: both log
  "Shutdown requested", cancel every coin task, save state and exit with no
  traceback and no hang.
  On top of that, spawn_coin() does for one coin exactly what startup does for
  all of them, in the same order: load its state file, give it a command queue
  and a price slot, reconcile the tracked position to the exchange (live only;
  a no-op for a flat coin, but it matters if an old state file came back with
  it), register it in `enabled` + COINS as ONE shared dict, then start its task.
  So the dashboard's "+ Add coin" with Enabled=True starts trading immediately,
  and flipping Enabled on a disabled coin starts it too. Turning a coin OFF
  still needs a restart -- stopping a task mid-cycle with an open position and
  possibly a resting order is a different problem, and not one to solve by
  cancelling a task.
  New coins still default to DISABLED in the add form: adding and starting are
  now separate decisions, which is the point.
  FIX found while testing: a coin added while disabled was written to config.py
  but never appeared in the dashboard, because the snapshot's inactive list is
  built from the in-memory COINS -- so it was invisible, including to the toggle
  that would have enabled it. add_coin_api now registers the entry in COINS
  immediately (replacing any same-symbol entry so one dict is shared), and
  removing a coin that isn't running unregisters it. A REMOVED coin that is
  still running keeps its slot and stays listed as active, because it genuinely
  is still trading until the restart.

Sep 9 - code-review fixes (7 findings).
  1. PAPER WALLET COULD GO NEGATIVE (helpers/wallet.py). spend() debited
     unconditionally and nothing checked the balance first, so paper mode kept
     buying with money it did not have -- PaperWallet(100) after three $100 buys
     held -$200. With 13 coins x max_grid_levels x usd_per_buy (~$18,200) against
     a $650 pool the strategy was never capital-constrained the way it is live,
     which made the paper wallet, the dashboard's portfolio card and every paper
     PnL comparison fiction. Replaced with try_spend(), which checks and debits
     under the SAME lock (two coins buying on one tick cannot both pass the
     check). paper_buy() now returns None when the pool is short and execute_buy
     logs and skips instead of booking a position; the paper limit-buy fill drops
     the resting order. Verified live: 5 forced buys against a $50 pool were all
     refused, wallet stayed $50.00, zero positions booked.
  2. PAPER LIMIT-BUY NEVER PAID ITS FEE (helpers/coin_runner.py). The fill
     debited `gross` while _finalize_buy recorded qty*price + fee as the cost
     basis, so a $100 fill left $0.20 unpaid -- PnL pessimistic by the fee,
     wallet optimistic by the same amount, and the two never reconciled. Every
     coin uses buy_order_type "limit" and the log holds 264 such fills. Now
     debits gross + fee, matching the market path, which was already consistent.
  3. SILENT PHANTOM SELL (helpers/coin_runner.py). check_pending_sell treated a
     live order reported closed with filled<=0 as a full fill with no warning:
     the position is wiped, cycle_count increments and realized PnL is credited
     for a sale that never happened, while the coins sit on Kraken. The buy side
     already logged a warning for exactly this. Added the matching warning so the
     more damaging direction is visible. (Behaviour unchanged -- a real cancel
     reports canceled/expired, not closed -- this is about being able to see it.)
  4. Unclosed file handle in content_type() (helpers/icons.py), called on every
     icon request; now uses a context manager.
  5. set_fields() duplicated the temp-file / parse-check / backup / os.replace
     sequence that _commit() already implements for add_coin and remove_coin.
     Folded onto _commit with its own verify callback: one definition of how
     config.py is safely replaced, ~15 lines gone. Rejection paths and the
     comment/format-preserving round trip re-verified.
  6. Removed ACTION_BY_KIND (helpers/actions.py) -- built at import, never read.
  7. Removed the blynklib pin (helpers/requirements.txt) -- nothing imports it;

Sep 13 - SECURITY: dashboard request guard + pinned icon downloads.
  Found by a vulnerability scan and PROVEN against sandbox copies first.
  1. CROSS-SITE REQUEST FORGERY from another port on the same host. Browsers
     count every port of a hostname as one "site", so SameSite=Lax still sent
     the login cookie with a hidden form posted from any other app on the box;
     and aiohttp's request.json() ignores Content-Type, so the form's text/plain
     body parsed as a real command. Proof: a page on :8792 made the dashboard on
     :8793 queue a command. Now every state-changing request must be
     application/json (a form can't send it; a cross-origin fetch sending it
     needs a CORS preflight that is never granted), a browser-supplied Origin
     must match this host, and requests browsers label cross-site/same-site
     may navigate to the page but not call the API.
  2. DNS REBINDING in no-token loopback mode (which the code allows, and the
     SSH-tunnel setup uses). Nothing checked the Host header, so a malicious
     site could point its domain at 127.0.0.1 and get full control. Proof: a
     spoofed Host with no token read the snapshot and queued a command. Now the
     dashboard only answers to localhost, this machine's own hostname and any
     IP literal (a rebinding attack can only arrive under a domain name), plus
     DASHBOARD_ALLOWED_HOSTS for a proxy domain. A refused name is logged once
     with the exact value to add.
  4. ICON DOWNLOADER trusted URLs from CoinGecko's JSON with no scheme/host
     check; http:// to LAN addresses would have been requested if that data were
     ever tampered with (file:// was only blocked by accident). Fetches are now
     pinned to https:// on CoinGecko hosts, re-checked on every redirect hop.
  Verified: 15 guard rules unit-tested; both attacks re-run and refused
  (rebinding 403, nothing queued; forged posts 415/403); the dashboard's own
  page, scripts with the token header, and real icon downloads still work.
  New optional setting DASHBOARD_ALLOWED_HOSTS (config.py / .env.example).
  NOTE: needs a restart. Reach the dashboard by IP, localhost or the server's own
  hostname -- any other name needs adding to DASHBOARD_ALLOWED_HOSTS.
